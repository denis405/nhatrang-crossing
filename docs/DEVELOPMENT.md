# Разработка

**Правило проекта: на хосте ничего не запускается.** Node, npm, тесты, сборка — только в Docker. На машине нужны только Docker и Docker Compose v2.

## Запуск

```bash
docker compose --profile dev up --build dev
```

Vite с hot reload на http://localhost:5173. Исходники примонтированы в контейнер, `node_modules` лежит в именованном томе `frogger_node_modules`. В контейнере включён polling файлов (`VITE_POLL=1`): события ФС с macOS через bind mount доходят ненадёжно.

**С телефона** в той же Wi-Fi сети: `http://<IP мака>:5173`. IP можно узнать так:

```bash
ipconfig getifaddr en0
```

Если macOS спросит про входящие соединения для Docker, разреши.

Остановить:

```bash
docker compose --profile dev down
```

## Тесты, баланс, отладка

```bash
docker compose run --rm dev npm test
```

```bash
docker compose run --rm dev npm run typecheck
```

```bash
docker compose run --rm dev npm run sim -- 60
```

```bash
docker compose run --rm dev npx tsx sim/debug.ts 1 rusher
```

- `npm run sim -- N` — для каждой улицы и каждого бота прогоняет N seed'ов. Выводит процент выживших, среднее время перехода, среднее число near miss и разбивку причин смерти.
- `sim/debug.ts <индекс улицы> <бот> [номер seed]` — находит первую смерть и печатает последние 40 тиков: позицию пешехода, линию, которую видят водители, EMA и состояние каждого байка рядом (`x`, `y`, домашняя полоса, выбранная сторона `s`, допустимая зона).

Боты (`src/game/bots.ts`):

| Бот | Поведение |
|---|---|
| `perfect` | тап ровно каждые `tempo` |
| `jitter10`, `jitter25` | интервал `tempo × (1 ± 10 % / 25 %)` |
| `rusher` | интервал `0.65 × tempo` |
| `freezer` | один раз замирает на 1.2 с в первой байковой полосе |
| `flincher` | после 15 % шагов делает лишний тап через 0.1 с |

Все боты перед выходом с тротуара или островка «смотрят»: симулируют идеальный переход на копии мира.

### Текущий баланс (60 seed'ов)

| Улица | идеальный | ±10 % | ±25 % | торопыга | замирает | дёргается |
|---|---|---|---|---|---|---|
| 1. Переулок у Чо Дам | 100 % | 100 % | 100 % | 88 % | 93 % | 97 % |
| 2. Нгуен Тхьен Тхуат | 100 % | 98 % | 93 % | 75 % | 80 % | 93 % |
| 3. Чан Фу днём | 100 % | 92 % | 68 % | 18 % | 40 % | 23 % |
| 4. Хунг Выонг | 100 % | 87 % | 75 % | 30 % | 48 % | 40 % |
| 5. Ле Тхань Тон | 100 % | 85 % | 57 % | 33 % | 55 % | 83 % |
| 6. Чан Фу вечером | 100 % | 87 % | 55 % | 8 % | 38 % | 22 % |
| 7. Круг у башни Трам Хыонг | 100 % | 65 % | 52 % | 18 % | 40 % | 10 % |
| ∞ улица 1 | 100 % | 100 % | 98 % | 70 % | 68 % | 93 % |
| ∞ улица 6 | 100 % | 97 % | 92 % | 68 % | 88 % | 82 % |
| ∞ улица 11 | 100 % | 88 % | 87 % | 45 % | 72 % | 68 % |
| ∞ улица 21 | 100 % | 85 % | 60 % | 38 % | 42 % | 52 % |

Строки «∞» прогоняют новую сгенерированную улицу на каждом seed. У каждой улицы свой характер: на Ле Тхань Тон (одностороннее движение) прощаются нервные двойные тапы, но много туристов; на Хунг Выонг и Чан Фу почти все смерти от машин и автобусов.

Ориентир: обучение прощает почти всё, сложность растёт от улицы к улице, а идеальный бот **всегда 100 %** — и на сюжетных улицах, и на сгенерированных. Это проверяется в `tests/avoidance.test.ts` и `tests/endless.test.ts` (там же: «торопыга» на улицах 3–7 выживает реже чем в половине случаев), и сборка падает, если инвариант нарушен.

### Режим «Ты — байкер»

```bash
docker compose run --rm dev npm run sim:ride -- 20 180
```

Аргументы: число seed'ов и длина заезда в секундах. Полная сложность наступает примерно к 110-й секунде. Сейчас (20 seed'ов, 180 с): «едет прямо» разбивается везде, медиана 187 м, чаще всего въезжает в местный байк; «смотрит вперёд» выживает 20/20 и проезжает 3051 м, в среднем 6 «бип-бип». Ручки в начале `src/game/ride.ts`: `V0`/`VMAX` (скорость), `RAMP` (как быстро растёт сложность), `RIDE_STEER` (руль); веса типов и интервалы — в `spawnWalkers` и `spawnNpc`.

## Как добавить улицу

1. Добавить объект в `LEVELS` (`src/game/levels.ts`): полосы снизу вверх через хелперы `sidewalk()`, `bikes(dir, spawn)`, `cars(dir, spawn)`, `median()`.
2. Запустить `npm run sim` и подкрутить плотность (`every`), скорость, состав (`kinds`), `drivers.margin` и `drivers.reaction`.
3. Запустить `npm test`: инвариант «идеальный проходит» проверяется для каждой улицы автоматически.

Ручки сложности в порядке силы влияния:

| Ручка | Где | Эффект |
|---|---|---|
| `drivers.margin` | уровень | запас водителей в px; меньше — строже к любой ошибке |
| `drivers.reaction` | уровень | множитель реакции; больше — водители дольше не замечают остановку |
| `adapt` | уровень | 0 — водители ждут только норму (торопливость наказывается сильнее), 1 — подстраиваются под игрока |
| `tolerance` | уровень | ширина «ровной» зоны: влияет на звёзды и подсказки, не на физику |
| плотность, состав | полосы | больше туристов и грузовых байков — больше хаоса; машины — окна для перехода |
| `KINDS` | `vehicles.ts` | реакция, руль и запас по типам (глобально) |

## Иконки

```bash
docker compose run --rm dev npm run icons
```

`scripts/icons.ts` рисует иконку по пиксельной карте 32×32 и пишет PNG в `public/icons/` (192, 512, maskable 512, `apple-touch-icon` 180, favicon 32). Файлы лежат в репозитории, при сборке скрипт не нужен.

## Тексты

Всё лежит в `src/text/ru.ts`. Шутки и советы выбираются случайно из массивов, поэтому новые строки можно просто дописывать.

## Зависимости

После изменения `package.json` нужно обновить lock-файл и пересобрать dev-образ. Том `node_modules` при этом пересоздаётся:

```bash
docker run --rm -v "$PWD":/app -w /app node:22-alpine npm install --package-lock-only
```

```bash
docker compose --profile dev down -v && docker compose --profile dev build dev
```

## Превью в Claude Code

`.claude/launch.json` содержит конфигурацию `dev (docker)`: она поднимает тот же `docker compose --profile dev up`.

## Стиль кода

- TypeScript strict, без фреймворков.
- Симуляция (`src/game`) не трогает DOM и `Math.random`, весь случай идёт через `Rng`. Иначе ломаются детерминизм и боты.
- Комментарии объясняют «почему», а не «что».
