# Деплой на GitHub Pages

Игра — статика, поэтому ей подходит бесплатный статический хостинг. GitHub Pages сам выдаёт HTTPS-сертификат и раздаёт файлы через CDN по всему миру. Это решает обе проблемы прод-сервера: нет HTTPS, и из части стран сайт не открывается (см. [DEPLOY_PROD.md](DEPLOY_PROD.md), «Особенности сервера», п. 5).

## Что уже готово в репозитории

| Файл | Что делает |
|---|---|
| `.github/workflows/pages.yml` | При каждом пуше в `main` ставит зависимости, гоняет тесты, собирает игру и публикует `dist` на Pages. Если тесты или `tsc` падают, сайт не обновляется. |
| `vite.config.ts` | `base` берётся из `BASE_PATH`. Pages-проект живёт по адресу `/<репозиторий>/`, и workflow передаёт этот путь сам. Без переменной (Docker, локальная разработка) — `/`, как раньше. |
| `public/manifest.webmanifest` | `start_url` и иконки — относительные пути, работают и в корне, и в подпапке. |
| `src/share.ts` | Ссылка в «Поделиться» ведёт на адрес игры с учётом подпапки, а не на корень домена. |

Сборка с `BASE_PATH=/frogger/` проверена локально: игра открывается из подпапки, манифест и иконки отдаются, тесты проходят.

## Что сделать (один раз)

1. **Аккаунт.** Войдите на [github.com](https://github.com) или зарегистрируйтесь.
2. **Репозиторий.** Создайте новый **публичный** репозиторий, например `nhatrang-crossing`, без README и `.gitignore` (они уже есть). На бесплатном тарифе Pages работает только для публичных репозиториев.
3. **Включить Pages.** В репозитории: Settings → Pages → Build and deployment → Source: **GitHub Actions**.
4. **Залить код.** Из корня проекта на маке (подставьте свой логин):

   ```bash
   git remote add origin https://github.com/<логин>/nhatrang-crossing.git
   ```

   ```bash
   git push -u origin main
   ```

   При первом пуше git попросит войти в GitHub (откроется браузер или нужен токен вместо пароля).
5. **Дождаться сборки.** Вкладка Actions → «Deploy to GitHub Pages», 1–2 минуты. Адрес игры:

   `https://<логин>.github.io/nhatrang-crossing/`

   Он же появится в Settings → Pages.

## Обновление

Закоммитить и `git push`. Через пару минут новая версия на сайте. Откат — `git revert` плохого коммита и пуш.

## Свой домен (по желанию)

Settings → Pages → Custom domain, затем DNS-запись `CNAME` на `<логин>.github.io` у регистратора. Поставьте галочку Enforce HTTPS после выдачи сертификата. С собственным доменом игра живёт в корне, workflow сам соберёт её с `base: /` — менять ничего не нужно.

## Альтернатива: Cloudflare Pages

Тот же код работает без изменений: Workers & Pages → Create → Pages → подключить репозиторий с GitHub. Настройки сборки:

| Поле | Значение |
|---|---|
| Build command | `npm run build` |
| Build output directory | `dist` |
| Переменная окружения | `NODE_VERSION` = `22` |

Игра будет по адресу `https://<проект>.pages.dev/`. Workflow для GitHub Pages тогда можно удалить или оставить — он не мешает.
